# PrintParkk

Next.js 14 (App Router) + TypeScript + Tailwind (CDN) + MongoDB clone of the
PrintParkk homepage design, with a working Node.js backend (Next API routes),
email marketing, and SEO/AEO/GEO built in.

## What's included
- Full responsive homepage (hero, trust bar, latest designs, categories,
  packages/secure checkout, how it works, testimonials, FAQ, CTA, footer)
- Mobile hamburger nav (`#mobile-dashboard`) + sub-pages for every nav link
- MongoDB (Mongoose) models: Design, Category, Package, Testimonial,
  Quote, Subscriber — all content is DB-driven with safe in-code fallbacks
  if the DB is empty/unreachable, so the site never breaks
- Working "Get a Quote" contact form → saves to MongoDB + optional email alert
- Working newsletter signup → saves subscriber + optional welcome email
  (email marketing, via `lib/mailer.ts` + Nodemailer/SMTP)
- SEO: per-page metadata, Open Graph/Twitter cards, canonical URLs,
  `sitemap.xml`, `robots.txt`
- AEO/GEO: JSON-LD structured data (Organization, Service, FAQPage),
  a visible FAQ section, and `public/llms.txt` for AI answer engines
- Page speed: self-hosted `next/font` (no render-blocking Google Fonts),
  `next/image` with AVIF/WebP + priority hero image, gzip compression,
  security headers, GA script only loads if `NEXT_PUBLIC_GA_ID` is set

Images use real photographs (picsum.photos / randomuser.me) as stand-ins by
default — see **"Getting real, functioning images"** below to swap these
for actual matching apparel photography with one command.

## Getting real, functioning images

`data/images.json` already ships with real, working image URLs generated by
**Pollinations.ai** — completely free, no signup, no API key. `Hero.tsx` and
`scripts/seed.mjs` both read from this file, so the site is already showing
real AI-generated design artwork (skull, lion, astronaut, anime, vintage,
wolf/mountain designs) out of the box.

**To regenerate with different prompts/styles (still 100% free):**
```bash
# edit the prompts/seeds in scripts/generate-designs.mjs, then:
npm run generate-designs
npm run seed
```
Each URL calls `https://image.pollinations.ai/prompt/...` which generates a
real image on first request (~10-20s), then it's cached for instant loads
after. No account needed — this is the free option.

**Other options, if you want them:**

- **Real stock photography instead of AI art** — get a free key at
  https://www.pexels.com/api/, then:
  ```bash
  PEXELS_API_KEY="your-key" npm run fetch-images
  npm run seed
  ```
- **Your own actual design files** — upload to
  [Cloudinary](https://cloudinary.com) (25GB free) or
  [imgbb.com](https://imgbb.com), then paste the URLs into
  `data/images.json` directly and run `npm run seed`.

I can't hotlink other brands' copyrighted merchandise photos (e.g. the
specific product shots you'd find on Pinterest/clothing-brand sites) — the
three options above are the legitimate ways to get real, working images.

## 1. MongoDB Atlas (free tier)
1. Create a free cluster at https://cloud.mongodb.com
2. Database Access → add a user + password
3. Network Access → Allow access from anywhere (0.0.0.0/0)
4. Copy the connection string into `MONGODB_URI`

## 2. Run all steps (Termux / local)

```bash
cd printparkk
cp .env.example .env
# edit .env and paste your MONGODB_URI (and SMTP_* if you want email)

npm install
npm run seed          # populates designs/categories/packages/testimonials
npm run dev            # http://localhost:3000
```

## 3. Push to GitHub

```bash
cd printparkk
git init
git add .
git commit -m "Initial commit: PrintParkk site"
git branch -M main
git remote add origin https://github.com/<your-username>/printparkk.git
git push -u origin main
```

## 4. Deploy to Render

**Option A — via render.yaml (Blueprint), fastest:**
1. Go to https://dashboard.render.com/select-repo?type=blueprint
2. Connect your GitHub repo → Render reads `render.yaml` automatically
3. Fill in the env vars it asks for (MONGODB_URI is required, rest optional)
4. Click Apply — Render builds and deploys

**Option B — manual Web Service:**
1. https://dashboard.render.com → New → Web Service → connect your repo
2. Environment: `Node`
3. Build Command: `npm install && npm run build`
4. Start Command: `npm start`
5. Add env vars from `.env.example` (at minimum `MONGODB_URI`)
6. Create Web Service

After the first deploy, run the seed script once, pointed at your Atlas DB
(from your machine or Termux — not on Render itself):

```bash
MONGODB_URI="your-atlas-uri" npm run seed
```

Then set `NEXT_PUBLIC_BASE_URL` to your live Render URL
(e.g. `https://printparkk.onrender.com`) and redeploy so SEO tags/sitemap
point to the right domain.

## Notes
- **Pollinations image first-load speed:** each AI image generates on its
  first request (~10-20s), then is cached and instant after. This is fine
  on Render (a persistent server, not serverless) — the very first visitor
  to load a fresh URL may see a brief image delay, everyone after doesn't.
- Render free tier spins down on inactivity — first request after idle can
  take ~30s (cold start). Upgrade to a paid instance to avoid this.
- Tailwind is loaded via CDN script in `app/layout.tsx` per your request —
  no `tailwind.config.js`/PostCSS build step needed.
